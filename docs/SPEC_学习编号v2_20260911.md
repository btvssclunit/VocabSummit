## 1. 格式

```
规范形（存储与比较）   VS4K7M2Q3        9 字
显示形（给人看）        VS-4K7M-2Q3      11 字
```

| 段 | 位置 | 字符集 | 含义 |
|---|---|---|---|
| `VS` | 0–1 | 字面量 | 固定前缀，与 恢复码 的保留前缀同一个（§7） |
| 随机体 | 2–7 | `23456789ABCDEFGHJKMNPQRSTUVWXYZ` 6 位 | **随机**，由服务端签发（§4） |
| 校验位 | 8 | 同上 | §2 |

```js
var VSID_RE = /^VS([2-9A-HJKMNP-Z]{6})([2-9A-HJKMNP-Z])$/;
```

**编号里既没有学校、也没有顺序，两件都是刻意的。**

- **没有学校**（owner 2026-09-11 推翻第一稿）：学生会转学，而缩写会撞
  （实测 146 所学校用「英文首字母截 4 位」算，66 所落进 24 个撞号的代号，
  `BVSS` 本身就是 Bedok View 与 Bukit View 两所）。学校归属住在 `profile.school`，
  那也是 `firestore.rules` 唯一认的地方；编进编号只会制造第二个会漂移的真相来源。
- **没有顺序**（owner 2026-09-11：「prevent the problem of counting and figuring out
  classmate's id」）：顺序号是可以**从自己的号数到同桌的号**的。这不是抽象的风险，
  是一间教室里最现实的那一种。随机之后，就算有人真的撞出一个合法编号，
  **它也不告诉你那是谁的**——而针对性正是这里唯一值得防的东西。

字母表沿用 v1 的 31 个字符（无 `0 O 1 I L`）：这串东西要被写在纸条上、由十一岁的
孩子照抄。**比 v1 还短一个字**，学生每台设备少打一个字符。

### 6 位够不够（owner：「several schools are interested already」）

空间 31⁶ = **887,503,681**。编号**永不回收**，耗的是累计签发量，不是在籍人数——
**旧的那 1000 个不是「1000 个学生」，是「这辈子 1000 个」**，一所中学四届就用完了。

| 学校数 | 十年累计签发 | 占用率 | 盲猜命中 | 签发时撞号重摇率 |
|---|---|---|---|---|
| 5 | 17,500 | 0.0020% | 1/50,714 | 0.002% |
| 20 | 70,000 | 0.0079% | 1/12,678 | 0.008% |
| 146（全国） | 511,000 | 0.0576% | 1/1,736 | 0.058% |

**唯一性不靠运气，靠服务端。** 随机 6 位在 50 万个号的规模上生日碰撞是**必然**发生的，
所以签发端必须逐个做原子占位（§4），撞了就重摇——上表最后一列是重摇的频率，可以忽略。

「盲猜命中 1/1,736」看着不小，但**猜中一个合法编号一文不值**：它是用户名，
密码（31⁸ ≈ 8.5×10¹¹，§6）独自扛住全部，而且盲猜出来的号不属于任何特定的人。

## 2. 校验位：位置加权和 mod 31

```js
/* 学习编号 校验位。⚠️ 这不是哈希（v1 用的是 FNV-1a mod 31，实测漏检 ~4%）。
   位置加权和 mod 31：body 里任何**一个字符打错**、任何**一对相邻字符对调**，
   100% 检得出来。31 是质数、每个权重都 < 31、每个字符的值都 < 31，
   所以 weight×Δ 在 Δ≠0 时永不 ≡ 0 —— 这就是全部证明。
   ⚠️ 字符的值取的是**它在字母表里的下标**（0–30），不是 charCode。 */
var VSID_ALPHABET = "23456789ABCDEFGHJKMNPQRSTUVWXYZ";   // 31，质数
function _vsidCheck(body) {
  var s = 0, i;
  for (i = 0; i < body.length; i++) s += (i + 1) * VSID_ALPHABET.indexOf(body.charAt(i));
  return VSID_ALPHABET.charAt(s % 31);
}
```

**校验位在有密码之后为什么还留着**：它让「你编号打错了」这句话**在本机就说得出来**，
一次网络请求都不发。没有它，打错编号与打错密码回来的是同一句「编号或密码不对」，
而十一岁的孩子分不出该改哪一个。顺带它也不泄漏「这个编号存不存在」——判断全在客户端。

### 实测（60,000 个随机 body 穷举所有单字符替换与相邻对调）

|---|---|---|
| 任一位单字符打错 | 10,800,000 | **0** |
| 相邻两位对调 | 290,271 | **0** |

## 3. 🔴 先读这一节：账号为什么必须由服务端建

随机编号挡掉了**针对性**（数不到同桌的号，§1），但它**没有**挡掉下面这条，
所以「客户端自己建账号」依然不行：

> `createUserWithEmailAndPassword` **不核对任何东西**——它是**设定**密码，不是**验证**密码。
> 客户端建账号 ⇒ 任何人都可以拿一个自己编的、合法形状的编号去注册，
> 而那个编号将来可能正好被签发给某个学生。那个学生拿着纸条登录，
> 只会看到「密码不对」，而且没有任何办法自证。

要挡住它，必须有人在建账号之前回答一句**客户端回答不了的问题**：
「这个编号，是不是我们真的发出去的、而且还没被认领？」
那需要 Admin SDK，也就是一个特权端点——

**而 owner 要的「teacher reset password button」需要的正是同一个端点。**
两件事合起来只需要一个，不是两个。

## 4. 一个特权端点，三件事

客户端拿不到 Admin SDK，而以下三件事都必须用它：

| 操作 | 谁调用 | 做什么 |
|---|---|---|
| `issueBatch(n)` | HOD / SH / superadmin | 摇 n 个随机编号，**逐个原子占位**（`vsidGrants/{vsid}` 的 `create`，撞了就重摇），**建好 n 个 Firebase Auth 账号**，各带一个随机初始密码，把「编号+密码」返回一次给老师下载成 CSV |
| `resetPassword(uid)` | HOD / SH / superadmin | 生成新密码，`admin.auth().updateUser`，**只返回一次**，不入库 |
| `claimVsid(vsid, pw)` | 学生（见 §5） | 把学生现有的匿名账号就地升级成这个编号的账号，**uid 不变** |

```js
// 端点内部必须自己重新做一次权限检查：Admin SDK **完全绕过 firestore.rules**。
const staff = await db.doc(`teachers/${ctx.auth.uid}`).get();
```

> 规则文件顶上那句「Always test rights with isSchoolManager()」在这里也算数：
> 端点与规则必须同时改。

**新密码只返回一次，永不写进 Firestore。** 老师抄到纸条上。

## 5. 学生这一侧：认领，不是注册（uid 保住）

`admin.auth().updateUser(uid, { email, password })` 可以给一个**现有的匿名账号**
补上邮箱与密码，**uid 不变**。这一条是整套迁移策略的支点：

```
学生：匿名 uid（已经有进度、有 users/{uid}、scores/{uid}、dockScores/{uid}）
  ↓ 打进纸条上的 编号 + 初始密码
claimVsid()：核对 vsidGrants/{vsid} 未被认领
          → updateUser(匿名uid, {email:"VS012345K@vocabsummit.firebaseapp.com", password})
          → 标记已认领
  ↓
同一个 uid，现在可以在任何设备上用编号+密码登录
```

**零迁移。** 现有 250 多个百德学生的 `users/{uid}`、排行榜行、教师后台的行，
一个字节都不用搬。这比「预建账号 + 首次登录把本机数据推上去」干净得多，
后者要在两个 uid 之间搬家，而 `localStorage 才是权威` 这条前提让那段搬家代码
有一个很难测的失败模式。

> ⚠️ **落地前先花五分钟验一次** `updateUser` 对匿名账号加 email/password
> 到底行不行（拿一个丢弃账号试）。整个 §5 挂在这一条上。
> 这份文件是根据文档写的，**不是在这个项目里测出来的**。

> ⚠️ **共用 Chromebook 的陷阱**：认领会把**这台机器上现在这份匿名档案**
> 绑到这个编号上——那可能是上一个学生的。认领前必须有一屏
> 「这是你吗？（昵称／班级／海拔）」，选「不是我」就先开一个干净的匿名身份。

## 6. 密码

**8 位，取自同一个 31 字母表**（无 `0 O 1 I L`），显示成 `K7M2-QXVD`。

- 空间 31⁸ ≈ 8.5×10¹¹。编号是可枚举的，所以密码得独自扛住全部——
  加上 Firebase Auth 自带的频率限制，这个量级远够。
- Firebase 的密码下限是 6 位；取 8 是为了留余量，而学生**每台设备只打一次**。
- **老师签发，学生不能改。** 这一条把重置量压掉一个数量级：
  绝大多数「忘了密码」其实是「纸条找不到了」，而老师手上那份 CSV 还在。
  真要换（被人看见了），走的也是 §4 的同一个重置按钮。

**明文只存在两个地方：签发时那一次返回，和老师自己机器上的 CSV。**
Firestore 里没有，Auth 里是哈希。

## 7. 必须原样保住的两个行为

**(a) 形状判定宽松，校验失败要落到 恢复码 分支。**

   ④ 升级之后还读不读得到自己那份 `users/{uid}`（端到端走真规则）。
5. **分两次上线吗？** 建议：先上格式 + 端点 + 签发，**百德一个班先跑一轮**，
   确认重置按钮在学校网络下按得动，再开第二所学校。
